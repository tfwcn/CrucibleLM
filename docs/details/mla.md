# MLA：低秩压缩的 KV 缓存

> 一句话：KV 不存全文，只存一个 128 维的"摘要向量"，解码时再展开，用 1/10 的显存存同样的上下文。

## 痛点

标准注意力解码时，每个 token 的 K、V 都要留着，后面每生成一个字都要回看。
12 层 × 12 头 × 64 维 × 2（K+V）× 200K token × fp16 ≈ 2.4GB——还只是 KV，
加上别的就奔 16G 上限去了。上下文一长，KV 缓存是第一块天花板。

## 直觉

人读书不会背全文，记的是"梗概 + 几个关键词"。MLA 就是这个思想：
K/V 里真正有信息量的部分远小于 768 维，先压成 128 维存起来，
用的时候再展开。信息有损吗？有，但训练会逼着模型把精华塞进这 128 维。

## 原理

标准做法：`K = X·Wk`（768→768），存 `(T, 768)`。

MLA 做法分两步走：

1. 压缩：`c = X·Wdkv`（768→128），只存 `c`，这就是 latent；
2. 展开：`K = c·Wuk`（128→768）、`V = c·Wuv`（128→768），用完即扔。

压缩比 ≈ 768/128 = 6，算上 RoPE 解耦部分，实测约 1/10。
数学上这是给 K/V 加了个低秩瓶颈（rank=128），表达能力上限降了，
但 128M 小模型的瓶颈本来也不在注意力宽度，而在总量。

RoPE 为什么要"解耦"：旋转位置编码不能走压缩（转完再压会丢相位），
所以单独留 32 维 `qk_rope_dim` 走直通，不压缩。这是 DeepSeek 论文里
最关键的一个细节，抄的时候漏了它位置外推直接崩。

## 我们的实现

- 文件：`src/llm/local/mla.py`（`MLAModule`）
- 参数：`q_lora_rank=192`（Q 也压）、`kv_lora_rank=128`、`qk_rope_dim=32`
- 缓存：`_pack_cache` 静态装箱 `(buf_c, buf_kr, pos)`，预分配、按位写，
  不再 `cat` 增长（见《推理加速》）
- QK-Norm：Q/K 在点积前各自归一化，防某个头数值爆炸（Qwen3 系做法）

## 代价与坑

- 压缩是有损的：如果下游任务对长距离逐字引用敏感（比如从 200K 里抄原句），
  latent 会糊。200K 能"跑"是真的，能"背"则别指望。
- `rope_cos/sin` 缓存长度 = `max_seq_len`，输入超了会先报错（`forward` 里拦），
  别指望静默外推；要 200K 用 `longctx_config()`（YaRN×8，见《RoPE 与 YaRN》）。

## 一句话总结

KV 存梗概不存全文，显存砍到 1/10，代价是逐字记忆变糊——小模型的正确取舍。
