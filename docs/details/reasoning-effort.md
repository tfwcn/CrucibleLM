# 可控推理努力：一个标量 b ∈ [1,100] 控制成本–质量曲线

> 一句话：不改权重、不改解码参数，只在**系统提示**里加一行
> `Reasoning Effort: {b}`，让同一份 checkpoint 在"短而省"和"长而准"之间移动。
> 这份能力是**训练出来的**，不是提示词变魔术。

## 痛点

推理模型的成本几乎全在输出 token 上：同一道题，模型可能 200 token 答完，也可能
8000 token 绕三圈。部署方真正想要的是一个**连续的旋钮**：

- 延迟敏感（客服、补全）→ 小 b，允许掉一点准确率；
- 难题（竞赛数学、SWE）→ 大 b，把推理预算拉满；
- 中间地带 → 任意整数档，平滑过渡。

硬截断 `max_tokens` 做不到：它**在生成长度上切一刀**，被截断的回答通常直接错
（推理链断了），而不是"用更短的方式重答一遍"。

## 直觉

把"想多深"当成一个**可学习的条件**：训练时把同一道题按不同努力档各采样一批，
低档用重惩罚逼它短、高档几乎不罚让它长；推理时把档位写进提示，模型就按训练时
学到的那档行为来答。

## 原理（V4.1 §5.1.4 + 附录 C）

### 1) 条件化：一行指令

```
Reasoning Effort: {b} (range 1–100; higher values request more thorough reasoning)
```

论文逐字如此。换措辞等于换成一个**训练时没见过**的条件，效果不可预期——所以
`src/llm/local/effort.py` 里这行是常量，只替换数字。

### 2) 训练：同档比较 + 指数长度惩罚

每个 prompt x、每个档位 b 采样 M_b 条回答 `z_{b,j} ~ π(·|x,b)`，
**只有同 `(x,b)` 子组内的回答互相比较**（组内奖励减均值）：

```
A_{b,j} = r_{b,j} − mean_j r_{b,j}          # 子组内均值中心化
```

跨档放进同一组会怎样？高档天生更长、更容易做对，组均值被长回答抬高——优势函数
于是把"答得更长"当成"答得更好"，档位迅速坍缩。所以长度差不由优势函数表达，
而由**惩罚项**塑形：

```
r_len = −min( C_max , k(b)·ℓ / L_norm )        (eq. 11)
k(b)  = k0 · exp( −(b − b_min)/τ ),  τ = λ·Δb  (eq. 12)
```

- `k0`：整体"往短里压"的力度；
- `τ`：档位之间拉开多远（b 每 +τ，惩罚系数 ×1/e）；
- `C_max`：扣分上限（触顶后边际惩罚为 0，长回答不再被无限惩罚）。

### 3) 为什么指数衰减能让长度对 b 近似线性

附录 C 的一阶条件：`p'(ℓ) = k(b)/L_norm`；边际收益近似指数衰减
`p'(ℓ) ≈ a·exp(−ℓ/s)`。两式联立：

```
ℓ*(b) ≈ C_x − s_x·log k0 + s_x·τ·(b − b_min)      (eq. 16)
```

即**指数惩罚 ⇔ 最优长度对努力线性**。两条推论：

- `k0` 只平移整条曲线（整体压力），
- `τ` 只管斜率（档位敏感度）——所以 τ 才是"档位分离度"的那个旋钮。

### 4) 部署：三档 + 插值

| API 档 | b |
|---|---|
| `low` | 50 |
| `high` | 75 |
| `max` | 100 |

训练只覆盖有限几档，但推理可用任意 1–100 的整数（插值行为）。**前提**是训练时
档位足够密（如 25/50/75/100），中间值才有东西可插。


## 我们的实现

| 位置 | 内容 |
|---|---|
| `src/llm/local/effort.py` | 指令生成/幂等注入、档位解析、`penalty_coefficient`、`length_penalty`、`predicted_length`、`group_advantages` |
| `src/llm/local/infer.py` | `chat/stream(..., effort=...)` → 注入系统提示；`effort=None` 时**逐位等于**老路径 |
| `src/llm/local/server.py` | OpenAI 兼容端接受 `reasoning_effort` / `effort`（1–100 或档名），非流式与 SSE 都透传 |
| `scripts/effort_probe.py` | 探针：同 checkpoint 上实测"档位 × 平均输出 token × 命中率"，并检查单调性 |

| 参数 | 默认 | 说明 |
|---|---|---|
| `b` | `None` | `None` = 不注入指令（老客户端不变） |
| `k0` | 1.0 | 最低档的惩罚系数 |
| `b_min` | 1 | 训练档位的下界（最低档不惩罚衰减） |
| `τ` | 25 | `λ·Δb`；`λ=1`、档距 25 时等于 25 |
| `L_norm` | 1000 | 参考长度（token） |
| `C_max` | 1.0 | 最大扣分 |

## 实测

| 检查 | 结果 |
|---|---|
| 指令幂等 | 连注 3 次仍只有 1 行；换档位是替换不是追加 |
| `effort=None` | 编码后的 prompt 与老路径**逐 token 相同** |
| 惩罚数学 | `k(b_min)=k0`、`k(b_min+τ)=k0/e`、长度惩罚单调且触顶后不变 |
| eq.16 线性 | 预测长度对 b 的一阶差分恒定、二阶差分为 0 |
| 分组 | 组内优势均值 0；整组 +100 平移后优势不变（跨档不比较） |
| 探针（162.7M SFT checkpoint，未做努力档训练） | 长度**不单调**（25/50/75/100 → 49/24.7/49/36.3 token），命中率 0% —— 与预期一致：**没训过就不会有效果** |
| 单测 | `tests/test_effort.py` 21 项全绿；全量 491 passed |

## 代价与坑

- **这是训练出来的能力，不是提示词技巧**。实测把指令塞给未做过努力档训练的
  checkpoint，长度不单调、质量不涨（探针已把它量化）。上线前必须先用
  `--levels` 采样 + `k(b)` 塑形做过 RL（或至少 SFT 过档位条件）。
- **跨档比较会毁掉信号**：分组键必须是 `(prompt, b)`。把不同档放进一个 GRPO 组，
  等于用优势函数奖励"更长"。见 pitfalls 61。
- **`C_max` 触顶段没有梯度信号**：如果大量样本都顶在上限，`ℓ/L_norm` 的差异被
  完全抹平，档位分离度会退化。探针里看"平均长度是否贴着 cap"。
- **指令必须幂等**：客户端的重试、网关的重写都可能二次注入；不幂等会变成两行
  冲突的档位（"75" 和 "25" 同时出现），模型行为随机。见 pitfalls 62。
- **`τ` 太小学不动的档位、太大档位挤在一起**：`τ = λ·Δb`，先按档距取 `λ=1`，
  再用探针的斜率标定 `λ`。
- 只改提示不等于改 `max_tokens`：低档仍然受 `max_tokens` 硬上限约束；探针里若
  低档平均长度贴着 `--new-tokens`，说明上限卡住了曲线（本次实测就是如此，48 上限
  下 3/4 档位打满）。

## 本地训练冒烟（条件化链路是否可训）

`scripts/smoke_effort_train.py` 用合成数据验证"档位 → 长度"这条链路
（RTX 3080 Laptop，800 步约 40 秒）：

| 项 | 设置 |
|---|---|
| 档位 | 25 / 50 / 75 / 100，各对应一段固定回答 |
| 注入 | 生产同款 `apply_effort()` 写进系统提示 |
| 模型 | 0.92M，2 层，字符级分词器，`max_seq_len=256` |
| 监督 | 只监督回答段 + EOS（`labels` 掩掉提示） |
| 优化 | AdamW lr=1e-3 + cosine，batch 16，档位轮转 |

结果（贪心生成、每档 16 条，token 数不含 EOS）：

```
目标长度  3 / 10 / 21 / 38
实测长度  2 /  9 / 20 / 37      ← 600 步后稳定，严格单调
```

```bash
python scripts/smoke_effort_train.py --steps 800
```

**边界**：这证明"档位文本能进上下文、同一份权重能按档位改变输出长度、EOS 能学"。
它**不**证明"高档更聪明"——SFT 只学条件化，长度-质量的正相关必须由 RL
（`k(b)` 长度惩罚 + `(prompt, b)` 同档分组，见上文 eq.11/eq.16）在真实可验证奖励上训出来。


## 一句话总结

训练时"同档比较 + 惩罚随档位指数衰减"，推理时"一行指令 + 一个整数"——
一份权重同时给出低成本与高质量两个工作点，中间档位连续可调。
