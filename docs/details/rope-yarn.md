# RoPE 与 YaRN：位置编码和 200K 外推

> 一句话：位置信息藏进"旋转"里；训练只见 8K，推理靠 YaRN 把旋转调慢，撑到 200K。

## 痛点

Transformer 本来不认识顺序，全靠位置编码。绝对位置编码（学 8192 个位置向量）
外推即死——第 8193 个位置没见过。相对位置编码（RoPE）好得多，但训练 8K、
推理 200K 时，旋转转速还是对不上：高频维度转太多圈混叠，低频维度没转够。

## 直觉

RoPE 把每个维度看成不同转速的指针：位置 p 就转 p×θ。外推失败是因为
推理时的 p 超出了训练见过的圈数。YaRN 的办法：**把表盘调慢**（按维度
插值缩放），让 200K 的圈数"看起来像" 8K 的——指针还是那些指针，只是走慢了。

## 原理

- RoPE：`q' = q·cos(pθ) + rotate(q)·sin(pθ)`，不同维度 θ 不同
  （`rope_theta=10000` 定基准频率）；
- YaRN：`scale=2.0`（我们的配置）对中频维度做 NTK 感知的插值，
  本质是"训练短 + 推理时把位置除以一个系数"，让模型以为自己还在舒适区；
- MLA 里只有 32 维走 RoPE（`qk_rope_dim=32`），旋转成本极小，
  这也是解耦设计的附赠好处。

## 我们的实现

- 文件：`src/llm/local/rope.py`（`build_rope_cache`、`apply_rope`）、
  `src/llm/local/config.py`（`longctx_config()`：YaRN×8 + 稀疏 MLA 的 200K 预设）
- 参数：`rope_theta=10000.0`、`yarn_scale=2.0`、`max_seq_len=8192`（训练）
- 路线是"短训 + 外推 + 分阶段长上下文微调"，不是一步到位 200K——
  先让 8K 扎实，外推验证，再拿长数据泡一小轮。

## 代价与坑

- 外推不是免费的：200K 下注意力再稀疏也有信息损失，"能跑"≠"记得住"
  （见《稀疏注意力》的大海捞针警告）。
- `rope_cos/sin` 缓存长度 = `max_seq_len`，输入超了 `forward` 直接报错，
  别绕过它；静态缓存预留 L 可超 rope_len（空位被掩码），但**有效位**
  超了一样错——长会话截断逻辑是调用方的责任。

## 一句话总结

位置靠转，长度靠混：8K 训扎实，200K 靠 YaRN 把表盘调慢——外推是工程，不是魔法。
